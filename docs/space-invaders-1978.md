# Space Invaders 1978 reference

Gameplay now runs the original Midway `invaders` program in an Intel 8080 CPU,
replacing the approximate game rules. The ROM controls alien movement, shooting,
collision and framebuffer erasure, explosion timing, deterministic UFO scores,
extra ships and successive racks. The adapter only supplies cabinet inputs,
beam interrupts, the shift register and sound ports.

Primary references:

- [Original program disassembly](https://computerarcheology.com/Arcade/SpaceInvaders/Code.html)
- [Hardware and input/output ports](https://computerarcheology.com/Arcade/SpaceInvaders/Hardware.html)
- [MAME board timing and ROM hashes](https://github.com/mamedev/mame/blob/master/src/mame/midw8080/mw8080bw.cpp)

## Program data

`src/game/rom.ts` contains the original 8 KB program. H, G and E were reconstructed
from the disassembly. The F chip was taken from the
[emulator's byte array](https://github.com/jscrane/invaders/blob/master/romf.h),
because the disassembly includes diagnostic annotations in that region.
All four chips are checked against MAME's registered SHA-1 values:

| Address       | Chip | SHA-1                                      |
| ------------- | ---- | ------------------------------------------ |
| `$0000–$07FF` | H    | `ff6200af4c9110d8181249cbcef1a8a40fa40b7f` |
| `$0800–$0FFF` | G    | `16f48649b531bdef8c2d1446c429b5f414524350` |
| `$1000–$17FF` | F    | `537aef03468f63c5b9e11dd61e253f7ae17d9743` |
| `$1800–$1FFF` | E    | `1d6ca0c99f9df71e2990b610deb9d7da0125e2d8` |

The embedded CPU comes from [Martin Maly's 8080js](https://github.com/maly/8080js),
commit `c2a02472f806405295f89bdec1a3706d7fc12efb`, retaining its MIT/BSD notices
in `public/licenses/8080js.txt`. Its wrapper was changed to a per-game ES module
factory. Interrupt acknowledgement, delayed EI and instruction cycle counts were
corrected to Intel timings. All 256 opcodes are checked against the
[MAME Intel 8080 timing table](https://github.com/mamedev/mame/blob/master/src/devices/cpu/i8085/i8085.cpp).
The independent [8080PRE diagnostic](https://github.com/superzazu/8080/tree/master/cpu_tests)
also completed successfully. No application rule replaces ROM gameplay.

The CPU runs at `19,968,000 / 10` Hz; refresh is
`320 × 262 / (19,968,000 / 4)` seconds, about 59.542 Hz. Interrupts use RST 1 at
scanline 96 and RST 2 at scanline 224. Instruction overrun carries into the next
beam interval. Inputs select one player, three ships and the 1,500-point bonus
ship DIP setting. The stored snapshot was generated by booting the ROM and pulsing
the cabinet coin and one-player start switches. The resulting 8 KiB RAM, CPU
registers, interrupt enable/delay, HALT, cycle counter,
shift register, beam deadline and sound ports are stored in `src/game/boot.ts`.
Every game restores independent copies of that exact boot state. Start uses the
already prepared machine; Play again restores the snapshot. No rule or invented
RAM value replaces the native program. Boot-reference and snapshot-generation
tooling are not retained; changes to the ROM, CPU or timing require recreating the
snapshot from a verified boot and validating the recorded fixtures.

## Picture

The renderer reads the original 1-bit VRAM directly into a reusable ImageData
buffer, with fixed RGB overlay colors and an updated alpha byte for every pixel.
One putImageData call replaces thousands of per-pixel Canvas calls. Every
projectile, explosion, erased shield bit and intermediate alien position comes
from the native program. Idle, paused and game-over screens reuse their last
image; entry/exit transitions still repaint when needed.
Screen colors are fixed by coordinates, as in MAME's overlay: red at y=32–61,
green at y=184–239, white elsewhere; the bottom spare-cannon region is green.
The arcade stays black in both portfolio themes.

The full 224×256 image is presented at 3:4, so each physical pixel is 7/6 as tall
as it is wide. The cropped y=32–239 playfield consequently has aspect 12:13.
The earlier square-pixel rendering made aliens look wider relative to their
height. Sprite bytes were already correct; changing physical proportions fixes
that difference without shrinking or redrawing the sprites.

The HTML scoreboard, spare-ship display and Start/close/sound/touch controls remain
accessible site UI. The default HUD is 448px wide with 14px text and a 10px gap
between labels and scores. A ResizeObserver measures the game width; CSS zoom
scales the whole scoreboard and lower status row uniformly. There is no nowrap
or horizontal-only font transform. UFO bitmap digits use the same measured scale,
and spare cannons match the canvas cannon size. The life count occupies a fixed
slot so disappearing reserve icons do not move it.

`tests/fixtures/space-invaders-1978.hex` independently checks the exported
sprite bitmaps used by the site icon, idle preview and score overlay:

| Graphic                          | ROM address                                     | Logical dimensions |
| -------------------------------- | ----------------------------------------------- | ------------------ |
| Octopus, crab, squid             | `$1C00`, `$1C10`, `$1C20`; second frames +`$30` | 16×8               |
| Cannon and breakup frames        | `$1C60`, `$1C70`, `$1C80`                       | 16×8               |
| Player shot and impact           | `$1C90`, `$1C91`                                | 1×8, 8×8           |
| Alien explosion                  | `$1CC0`                                         | 16×8               |
| Squiggly, plunger, rolling shots | `$1CD0`, `$1CE2`, `$1CEE`                       | four 3×8 frames    |
| Alien shot impact                | `$1CDC`                                         | 6×8                |
| Shield                           | `$1D20`                                         | 22×16              |
| UFO and explosion                | `$1D64`, `$1D7C`                                | 24×8               |
| Score digits                     | `$1ED0–$1F18`                                   | 8×8 cells          |

## Sound

The invented oscillator/noise effects and start/win/game-over melodies were removed.
Native sound-port rising edges play byte-for-byte WAV recordings for the shot,
base explosion, alien hit, bonus base, four fleet tones and UFO hit. The UFO
recording loops while its native sound bit is active. The native amplifier bit,
mute control and page pause gate the audio; restarting/closing stops all channels.

Recordings: [source archive](https://github.com/jscrane/invaders/tree/master/sounds),
also represented by the [original-game sound archive](https://www.classicgaming.cc/classics/space-invaders/sounds).
Names, provenance and SHA-256 values are recorded in
`public/licenses/space-invaders-audio.txt`. These are recorded effects rather than
an electrical simulation of the analog sound board; speaker response, component
tolerances and browser resampling can affect the heard result.

## Checks

`node --experimental-strip-types tests/invaders.check.ts` checks all ROM hashes,
every exported sprite bit, deterministic native gameplay, original cannon controls,
beam-cycle carry, next-rack behavior and the 3:4 geometry. It also checks the full
snapshot against recorded initialization hashes, snapshot isolation, restored
EI/HALT behavior, and 2,700 frames against memory/CPU/sound hashes captured before
optimization. The reference
is in `tests/fixtures/space-invaders-initialization.json`. It is included in the
Node TypeScript project so build and WebStorm also check its types.

Additional checks cover all eight input masks and 64 transitions, 768 comparisons
of whole and split frame steps, seeded long games, natural game overs and restarts.
Split-step comparisons allow `1e-9` seconds of accumulator rounding error while
requiring identical CPU, memory, sound events and remaining game state. The
original 2,700-frame fixtures remain unchanged.

`node tests/arcade.check.mjs http://127.0.0.1:5174` checks every displayed VRAM
pixel and overlay color, desktop/mobile proportions, uniformly scaled UFO points,
keyboard/touch controls, restart, focus, scroll locking, transitions and decoded
audio output for each native sound cue, deferred engine loading and zero redraws
across 500 game-over ticks. The browser check uses a debugger to arrange test
states; production exposes no test API.

`node tests/arcade-input.check.mjs [development-url]` checks every keyboard alias,
overlapping aliases, real multitouch, keyboard/touch combinations, pointer capture,
button Space/Enter, focus/visibility release, restart and exit. The audit reproduced
an overlapping-input bug in the pre-optimization version. Input now tracks each
held key or pointer separately, preserving an action until its last source releases.

`node tests/arcade-audio.check.mjs [development-url]` verifies all ten WAV hashes
and twenty complete three-second PCM outputs against direct reference playback.
It covers sample mapping, loops, edge triggers, channel replacement, gate, mute,
pause, restart and timed start/mute/unmute/stop. Maximum mixed-output error is
`1.1920928955078125e-7`, within Float32 rounding tolerance `2e-7`; individual
samples match exactly. Missing AudioContext, HTTP 404, decode failure and rejected
resume are also checked. This verifies digital playback, not physical speaker latency.

`node tests/arcade-loading.check.mjs [site-url]` holds and fails module requests to
check shared preload, pending clicks, cancellation, repeated retry, current geometry
and scroll after delayed loading, menu rerenders, and close/resize before the first
animation frame. It also runs against the production build. Both browser checks
use Chrome remote debugging on port 9222.

## Earlier renderer/runtime-cache performance comparison

These measurements predate the generated snapshot and intent preload.

Measured before/after in the same Chrome 155 headless browser on macOS ARM64,
using `node tests/arcade.bench.mjs /tmp/arcade.json [site-url]`. Run Vite and Chrome
with remote debugging on port 9222 first. The benchmark measures 15 repeated
initializations, 8,100 simulation frames and 870 game-loop callbacks after excluding
the first 30 callbacks. The browser clock and input pattern are controlled; other
tests/builds were stopped during measurement. Results measure synchronous callback
work, excluding final browser paint, compositing, network load and mobile hardware.

| Metric                             | Before    | After    |
| ---------------------------------- | --------- | -------- |
| First native boot                  | 34.5 ms   | 35.4 ms  |
| Repeated initialization, mean      | 100.79 ms | 0.04 ms  |
| Simulation, mean per frame         | 0.438 ms  | 0.193 ms |
| Simulation + Canvas, mean callback | 1.064 ms  | 0.749 ms |
| Simulation + Canvas, p95 callback  | 1.30 ms   | 0.90 ms  |
| Initial JavaScript, gzip           | 88.75 KB  | 71.04 KB |

In that version, first boot still executed all 334 native startup frames. Repeated initialization
is over 99.9% cheaper and the measured loop costs about 30% less. The Canvas PNG
after 900 identical input frames is byte-for-byte identical, with SHA-256
`0f46a5fec31ab62167fdc8fa085fb380a50461d948bdb1ae0412be553c19b3a3`.
The arcade loads as a separate 18.65 KB gzip chunk when opened. Alien objects are
reused across frames; the boot copy and image buffer add roughly 198 KiB of memory.
These timings describe this benchmark, not guaranteed FPS or performance on every
device. Formatting, lint, production build, engine checks and the complete browser
checks passed after the changes.

Physical CRT brightness, phosphor persistence and analog speaker behavior are
not reproduced. Browser presentation remains refreshed by requestAnimationFrame;
the underlying machine advances on the native refresh period.
